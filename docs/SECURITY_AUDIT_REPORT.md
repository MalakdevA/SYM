## تفاصيل الإجراءات المنفذة في كل محور أمني (Security Breakdown)

### 1. إدارة متغيرات البيئة (Environment Configuration)
- **ما تم إنجازه:**
  - إنشاء محرك بيئة ذاتي وآمن `api/config/env.php` يعمل تلقائياً وبشكل أصيل (Native Zero-Dependency) لقراءة وتفسير ملفات `.env` و `.env.local` دون الاعتماد على برمجيات خارجية قد تشكل ثغرات سلاسل التوريد (Supply-Chain Attacks).
  - دمج قارئ البيئة داخل `api/config/db.php` وبوابة الدفع `api/fawry/config.php` لضمان سحب البيانات المشفرة مباشرة من الذاكرة فقط.
  - إدراج قواعد حجب قاطعة في ملف خادم الأباتشي `.htaccess` تمنع الوصول المباشر عبر المتصفح لملفات `.env`, `.env.*`, `.git`, `.sql`, `.log`.
  - إضافة ملف `lib/env.ts` على الواجهة الأمامية للتحقق من عدم تسريب أي متغيرات سرية داخل حزم الجافاسكربت.

### 2. حماية المفاتيح السرية وبيانات الاعتماد (API Secret Variables)
- **ما تم إنجازه:**
  - عزل كامل لمفاتيح الدفع الإلكتروني لفوري (`FAWRY_SECURITY_KEY`, `FAWRY_MERCHANT_CODE`) وبيانات اتصال قاعدة البيانات (`DB_USER`, `DB_PASS`).
  - منع استعراض أو تضمين أي مفتاح سري داخل كود المتصفح؛ الواجهة الأمامية تستخدم حصراً المتغيرات العامة التي تبدأ بـ `NEXT_PUBLIC_`.
  - تأمين نقاط نهاية الـ API ضد كشف الرموز السرية أو كلمات المرور؛ تم تصفية استعلام المستخدمين في `api/admin-users/index.php` لاستبعاد حقول `password` و `token`.
  - تشفير كلمات المرور باستخدام خوارزمية التشفير المتكيفة **BCRYPT** مع عامل كلفة عالي (`cost: 12`).

### 3. سلطة السيرفر وحساب الأسعار (Server-Side Price Authority)
- **ما تم إنجازه:**
  - منع التلاعب بالأسعار نهائياً (Anti-Tampering): في شاشات الدفع وطلب المنتجات (`api/checkout/index.php` و `api/fawry/initiate/index.php`)، لا يتم اعتماد أي سعر مرسل من المتصفح، بل يقوم السيرفر بحساب أسعار السكوترز وقطع الغيار والضرائب مباشرة من قاعدة البيانات.
  - حماية الإيدمبوتنسي (Idempotency Protection): ضمان عدم تكرار الخصم أو إنشاء أوردرين بنفس المرجع.
  - مطابقة المبالغ في الخطاف الشبكي (Webhook Verification): يتأكد السيرفر من تطابق المبلغ المدفوع في فوري مع القيمة المسجلة مسبقاً قبل تحديث حالة الطلب إلى "مدفوع".

### 4. التحقق والفلترة الصارمة للمدخلات (Validation & Sanitization)
- **ما تم إنجازه:**
  - **حماية الواجهة (Frontend):** إنشاء مخطط التحقق الموحد `lib/validations/checkout.ts` بالاعتماد على Zod، يفرض قواعد صارمة: الاسم ثلاثي هجائي لا يقل عن 8 أحرف، رقم الهاتف مصري معتمد من 11 رقماً (يبدأ بـ 010 أو 011 أو 012 أو 015)، وعنوان تفصيلي يمنع الكلمات العشوائية.
  - **حماية السيرفر (Backend):** تنقية وفلترة كافة المدخلات في `api/helpers/response.php` عبر دالة `sanitizeInputArray` و `sanitizeString` للوقاية من هجمات الحقن النصي XSS وحجب البايت الصفري (Null-Byte Injection).
  - الوقاية من حقن قواعد البيانات (SQL Injection): استخدام الاستعلامات المجهزة المربوطة بالمعاملات (Prepared Statements) حصراً في 100% من استعلامات المنصة.

### 5. وسيط المصادقة وقواعد الحماية (Auth Middleware & Security Rules)
- **ما تم إنجازه:**
  - وسيط الأدمن بالباك إند: دالة `requireAdminAuth()` في `api/helpers/auth.php` تتحقق من توكن الجلسة (Bearer Token) وتفرض صلاحية زمنية مدتها 24 ساعة للحد من مخاطر سرقة التوكن (Session Hijacking).
  - حماية مسارات لوحة التحكم: مكون `AdminGuard.tsx` يراقب المسارات في الواجهة ويمنع أي مستخدم غير مسجل أو لا يملك الصلاحية من فتح الصفحات، مع التوجيه التلقائي لتسجيل الدخول.
  - خصوصية العملاء (PII Masking): تم تفعيل تشويش بيانات العملاء (إخفاء الأرقام الوسطى من الهاتف والبريد والاسم) عند الاستعلام العام عن الضمان أو الأوردرات لمنع سحب هويات العملاء.
  - جدار حماية ترويسات الأمان (Security Headers):
    - `X-Content-Type-Options: nosniff`
    - `X-Frame-Options: SAMEORIGIN` (حماية ضد Clickjacking)
    - `X-XSS-Protection: 1; mode=block`
    - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (إلزام HTTPS)
    - `Content-Security-Policy`: منع تشغيل سكربتات خارجية غير مصرح بها.
  - حماية المرفقات: إنشاء `.htaccess` مخصص يمنع تشغيل أي ملف تنفيذي أو سكربت PHP داخل مجلد رفع الصور `/public/uploads/`.

### 6. تحديد معدل الطلبات (Rate Limiting & Anti-Bruteforce)
- **ما تم إنجازه:**
  - تم تعميم نظام تحديد معدل الطلبات (Rate Limiter) على **كافة** نهايات الـ API الحساسة، بنظام النافذة المنزلقة (Sliding-Window IP Throttling) مع إرجاع ترويسات RFC القياسية (`RateLimit-Limit`, `RateLimit-Remaining`, `Retry-After`):

| نقطة النهاية (Endpoint) | الحد المسموح (Limit) | الغرض الأمني المحقق |
| :--- | :--- | :--- |
| **تسجيل الدخول (`/api/auth/login.php`)** | 5 محاولات / 5 دقائق | صد هجمات التخمين وكسر كلمات المرور (Brute Force) |
| **إتمام الشراء (`/api/checkout`)** | 5 طلبات / دقيقة | منع طلبات الشراء الوهمية والإغراق |
| **دفع فوري (`/api/fawry/initiate`)** | 3 محاولات / 5 دقائق | منع استنزاف جلسات الدفع الإلكتروني |

## نتائج اختبارات الجودة والتوافق (Verification Results)
1. **TypeScript Type Safety:** تم تشغيل `npx tsc --noEmit` واجتياز الفحص بنجاح تام وبدون أي أخطاء (Zero Type Errors).
2. **PHP Syntax & Compilation:** تم فحص كافة ملفات الباك إند عبر مفسر PHP (`php -l`) واجتياز الفحص بسلامة تامة (Syntax Validated).
3. **HTTP 429 Status Code:** نظام الـ Rate Limiter تم ربطه بإرجاع رمز الخطأ القياسي `429 Too Many Requests` مع إشعار باللغة العربية ووقت الانتظار المتبقي.
